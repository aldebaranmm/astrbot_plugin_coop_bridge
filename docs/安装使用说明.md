# 桌宠自动刷视频 — 安装与使用说明

照着做即可。**命令里的路径请按你自己机器的实际安装位置替换。**

本说明对应版本（2026-10-27 实测通过）：

- `cortico-world-astrbot-0.9.3.zip`
- `cortico-world-web-0.1.0.zip`
- `AstrBot-Coopanion桥接插件-v0.9.2.zip`

---

## 0. 三个包分别是什么

| 包                                | 装到哪                                | 作用                                  |
| -------------------------------- | ---------------------------------- | ----------------------------------- |
| AstrBot-Coopanion桥接插件-v0.9.2.zip | **<br /><br /><br />AstrBot**（服务端） | 记忆读写、活动汇总、配对、远程推送                   |
| cortico-world-astrbot-0.9.4.zip  | **Coopanion 桌宠**（客户端）              | 刷视频主体：开浏览器、点开看、挑片、读收藏               |
| cortico-world-web-0.1.0.zip      | **Coopanion 桌宠**（客户端）              | 网页/接口取数（`web_fetch`、`web_bilibili`） |

> **0.9.4 相对 0.9.3 的唯一改动**：主动消息的送达方式默认从 `piggyback` 改成 `flush`。  
> 老版本装上去后，远程消息要等你先跟桌宠说话才捎带出来（表现得像"收到但不开口"）。  
> 0.9.4 改成拉到就唤醒，实测 4 秒内冒泡。**从 0.9.3 升级的机器请看 3.4.1。**

### ⚠️ 先分清你要装的是哪种

架构是 **一个服务端 + 多个客户端**：AstrBot 只在**一台机器**上跑（记忆库、配对都在那儿），  
其他电脑装的都是 Coopanion 桌宠客户端，通过网络连回那台 AstrBot。

- **给另一台电脑装桌宠客户端**（常见情况）  
  → 只装 **两个 Coopanion 包**（`cortico-world-astrbot` + `cortico-world-web`）  
  → 只做 **第 3 节** 和 **第 4、5 节**  
  → **第 2 节（AstrBot 服务端）不用做**，服务端已经跑在原来那台机器上了
- **这台机器要自己独立跑一套 AstrBot**（少见）  
  → 才需要第 2 节的桥接插件

两个 Coopanion 包**都要装**，缺了 web 包桌宠就没有取数工具。

## 1. 先找到目录

**Coopanion 数据目录**（下面记作 `$COOP`），常见位置：

```
D:\Coopanion\data\home\companion\
```

确认方法：看 Coopanion 的控制台，或找 `config.json`、`data\core-state.json` 所在目录。

扩展目录（下面记作 `$EXT`）：

```
D:\Coopanion\data\extensions\
```

> 如果这台机器装在了别处，以环境变量 `CORTICO_EXTENSIONS_DIR` 为准。

**AstrBot 实例目录**（下面记作 `$AS`）：

```
C:\Users\<用户名>\.astrbot_launcher\instances\<实例ID>\
```

插件目录：`$AS\core\data\plugins\`

---

## 2. 装 AstrBot 桥接插件（服务端）

```bash
# 1) 解压到插件目录，目录名必须是 astrbot_plugin_coop_bridge
解压 AstrBot-Coopanion桥接插件-v0.9.2.zip
  → $AS\core\data\plugins\astrbot_plugin_coop_bridge\

# 2) 重启 AstrBot 实例（必须，覆盖更新不会自动加载）
```

**验证**：

```bash
curl --noproxy '*' http://127.0.0.1:6190/bridge/health
```

返回 `{"ok": true, ...}` 且 `sources` 里 livingmemory/angel_memory/self_learning 都是 `available: true` 就对了。

再确认端点在（401 是对的，404 才是没注册）：

```bash
curl --noproxy '*' -o /dev/null -w "%{http_code}" -X POST \
  http://127.0.0.1:6190/bridge/video -H "Content-Type: application/json" -d '{}'
# 401 = 正常；404 = 插件没加载，回去检查第 2 步有没有重启
```

## 3. 装 Coopanion 桌宠扩展（客户端）

### 3.1 放包

```bash
解压 cortico-world-astrbot-0.9.4.zip → $EXT\node_modules\cortico-world-astrbot\
解压 cortico-world-web-0.1.0.zip     → $EXT\node_modules\cortico-world-web\
```

**注意**：`cortico-world-astrbot` 里必须带 `node_modules\playwright-core`，刷视频脚本靠它开浏览器。  
压缩包里已经带了，别删。

### 3.2 登记依赖（容易漏）

编辑 `$EXT\package.json`，在 `dependencies` 里加两项：

```json
{
  "name": "cortico-extensions",
  "private": true,
  "dependencies": {
    "cortico-world-astrbot": "file:./node_modules/cortico-world-astrbot",
    "cortico-world-web": "file:./node_modules/cortico-world-web"
  }
}
```

> **少了这一步扩展不会被加载**，表现为 world 列表里根本看不到它。

### 3.3 给 web 扩展加配置节（容易漏）

编辑 `$COOP\config.json`，在 `worlds` 里加一节：

```json
"worlds": {
  "desktop-pet": { ... },
  "astrbot": { ... },
  "web": {
    "enabled": true,
    "maxChars": 6000,
    "timeoutMs": 15000,
    "allowLocal": false,
    "allowHosts": []
  }
}
```

> 没有这节配置，world 会是 `status: missing`（装了但没实例化）。

### 3.4 确认刷视频开关

同一个 `config.json` 里，`worlds.astrbot` 至少要有：

```json
"enabled": true,
"douyinEnabled": true,
"bilibiliEnabled": true
```

### 3.4.1 从旧版升级：补一行 `wakeMode`（0.9.3 及更早装的要做）

在 `config.json` 的 `worlds.astrbot` 里加：

```json
"wakeMode": "flush"
```

不加这行的表现：远程消息（AstrBot 主动推来的）**拉到了但桌宠不开口**，  
要等你先在气泡里说句话，它才会捎带出来说。加了之后是拉到就唤醒，几秒内冒泡。

改完重启 Coopanion（杀掉 Core 进程，主程序会自动拉起；  
找进程：命令行含 `--import tsx` 且含 `boot.ts` 的 `Coopanion.exe`）。

### 3.5 重启 Coopanion

杀掉 Core 进程（主程序会自动拉起），或整个退出重开。  
（找进程：命令行含 `--import tsx` 且含 `boot.ts` 的 `Coopanion.exe`）

**验证**：

```bash
curl http://127.0.0.1:17788/api/worlds
```

应该看到：

```
astrbot   active   [... astrbot_favorites, astrbot_watch_video]
web       active   [web_fetch, web_bilibili]
```

如果 `web` 是 `missing`，用同一个接口看它的 `reason` 字段，通常是 3.2/3.3 没做。

## 4. 首次使用前的两件事

### 4.1 配对（把这台机器接到 AstrBot）

在 QQ 里对机器人发 **「配对」** → 拿到 8 位码 → 在 Coopanion 控制台的 AstrBot 页粘贴。  
配对成功后 `config.json` 里会出现 `identityLabel`、`deviceId`。

### 4.2 登录 B 站**网页版**（重要）

用桌宠刷一次 B 站，浏览器打开后，**在网页上扫码登录一次**。

> 客户端（桌面应用）和网页版是两套登录态。  
> 没登录网页版 → 抓不到收藏 → 只能按热门瞎挑。

登录状态存在扩展目录的 `.browser-profile-bilibili`，**登录一次以后都算登录**。  
登录后刷一次就会自动把收藏抓全（存到 `favorites.json`，24 小时内不重复抓）。

## 5. 怎么用

在桌宠气泡里说人话就行：

| 你说           | 它怎么做                         |
| ------------ | ---------------------------- |
| 「刷B站」        | 开浏览器真刷：翻 feed → 点开一条看 → 看完再翻 |
| 「多刷会儿」       | 本来就是不限时，你没叫停就一直看             |
| 「别看了」「停」「够了」 | 立刻停下                         |
| 「这条没意思，换一个」  | 划走换下一条                       |
| 「我收藏了什么」     | 读你的 B 站收藏并告诉你                |
| 「B站上搜 XXX」   | 用接口搜，一秒出结果                   |

### 内置的行为规则（已写进提示词，不用你教）

- **短视频看完**：≤5 分钟的看到播完才走
- **长片至少 5 分钟**：更长的看完 5 分钟再划走
- **说的就是眼前这条**：点开瞬间报标题+简介，不会嘴上念列表、屏幕放另一条
- **照你的收藏挑**：收藏过的 UP 主优先
- **避开两类**：工具/软件教程类、以及跟"大肥鱼"自己相关的
- **不连着看同一题材**：和最近 3 条撞词就降权

## 6. 排错

| 现象                            | 原因 / 处理                                               |
| ----------------------------- | ----------------------------------------------------- |
| world 列表里没有 web               | 3.2 的 `package.json` 没登记                              |
| `web` 状态 `missing`            | 3.3 的 `config.json` 配置节没加；看 `/api/worlds` 的 `reason`  |
| 报「实例 id undefined 与定义 id 不一致」 | World 实现类必须带 `readonly id`，且等于定义 id（本包已带，别改）          |
| envPrompt 读到别的内容              | `dataDir` 是各 world 共享的，envPrompt 必须写到自己的子目录（本包已处理）    |
| 刷了但记忆没写进去                     | `/bridge/video` 是不是 404？是 → AstrBot 没重启               |
| 抓不到收藏                         | B 站**网页版**没登录（4.2）                                    |
| 收藏只有一百多条                      | 旧版只取前 8 个夹的第 1 页；本版已改为全部分页抓完，删掉 `favorites.json` 重刷一次 |
| 只翻不看                          | 观看脚本没跑起来，确认 `playwright-core` 在不在                     |
| 桌宠不开口                         | 老问题：事件唤醒不可靠，让主人在气泡里直接说话最稳                             |
| 远程消息到了但不开口                    | `wakeMode` 不是 `flush`（见 3.4.1），老版本默认是 `piggyback`     |

## 7. 已知限制

1. **AstrBot 覆盖更新必须重启实例**才生效，仪表盘的重载对新代码无效。  
   （重启要用户在启动器 GUI 点；自己用命令行起会被会话回收，约 3 分 40 秒就没了。）
2. 记忆库会持续增长（活动汇总写得较勤），建议偶尔看一眼 livingmemory 的体积。
3. AstrBot 检测到主人离开后，会反复推同一句「能不能让我自己刷会儿B站」的询问。  
   桌宠对重复内容会自己选择不回答（回 `end_turn`），不会一直烦你 —— 这是它的判断，不是故障。

> ~~远程指令收到但桌宠不开口~~ —— 0.9.4 已修：默认 `wakeMode=flush`，  
> 实测消息到达后 4 秒内 `pet_say` 冒泡，在 `deepseek-v4.1-flash` 上没有出现坏流。
